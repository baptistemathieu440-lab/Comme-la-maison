# Startup strategy

A compact playbook for taking a business/product idea from hypothesis to launch plan. Work section by section; don't produce all of them unless asked — match depth to what the user needs right now.

## 1. Market research
- Define the problem and the target customer in one sentence each (JTBD framing: "When [situation], I want to [motivation], so I can [outcome]").
- Size the market top-down (TAM/SAM/SOM) AND bottom-up (realistic customer count × price) — flag when the two disagree.
- Pull evidence from public sources: search trends, review sites (G2, Trustpilot, App Store reviews), forums/Reddit, industry reports. Cite what's actually findable; never invent numbers — mark estimates as estimates.

## 2. Competitor analysis
- Build a table: competitor, positioning, pricing, core features, strengths, weaknesses, and the segment they under-serve.
- Include indirect competitors and "do nothing / spreadsheet / manual process" as a baseline competitor.
- End with a one-paragraph wedge: what gap is defensible and worth building for.

## 3. Business model
- Default to the Lean Canvas (problem, solution, key metrics, UVP, unfair advantage, channels, customer segments, cost structure, revenue streams) over the full Business Model Canvas — faster to iterate.
- Name the revenue model explicitly (subscription, transaction fee, marketplace take-rate, one-time, freemium) and why it fits this customer.

## 4. Financial model
- Build from unit economics up, not top-down: CAC, ARPU/AOV, gross margin, contribution margin, payback period, LTV, LTV:CAC ratio.
- Produce a simple 12–18 month projection (customers, MRR/revenue, costs, burn, runway) as a table the user can drop into a spreadsheet — don't fabricate false precision; state assumptions next to every driver number.
- Flag the 2–3 assumptions the model is most sensitive to.

## 5. MVP planning
- Start from the riskiest assumption (usually: will anyone pay, not can we build it). Design the smallest test that resolves it.
- Split scope into Now (ships in the MVP) / Next / Never-for-v1, and justify each cut.
- Prefer a "concierge" or "Wizard of Oz" test before writing code when validation is cheaper than a build.

## 6. Pricing
- Anchor on value metrics, not cost-plus. Map price to the unit the customer already measures value in.
- Sketch 2–3 tiers with a clear upgrade trigger between them; identify the tier that should convert best given the target segment.
- Sanity-check against the competitor table from step 2 and the LTV:CAC target from step 4.

## 7. Go-to-market
- Pick one primary acquisition channel to focus on first (not three) based on where the target customer already spends attention, and say why.
- Define launch sequence: waitlist/beta → soft launch → public launch, with a success metric per stage.
- List the first 5 concrete actions, each with an owner and a date, not vague strategy language.

## Output style
Default to tables and bullet lists over prose paragraphs. When numbers are estimates, say so inline. Ask for the target customer/segment up front if the user hasn't stated one — everything downstream depends on it.
